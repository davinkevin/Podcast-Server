= On Kubernetes

== Requirements

=== Architecture

The *Podcast-Server* docker images are built for `linux/amd64` only. `arm` architectures (including `Raspberry Pi`) are not supported.

=== Kubernetes Cluster

To run the *Podcast-Server*, you have to use a `Kubernetes` cluster. `Kubernetes` is used as a deployment platform, but you don't have to configure it for high availability. The main goal of the *Podcast-Server* is to be run in your local network, so managed `Kubernetes` distribution (like Google Kubernetes Engine, Azure Kubernetes Service, Elastic Kubernetes Service…) are not recommended.

You can install `Kubernetes` with:

* https://k3s.io/[K3S]
* https://microk8s.io/[MicroK8S]
* https://github.com/kubernetes/minikube[Minikube]
* https://www.docker.com/products/docker-desktop[Docker for Desktop with Kubernetes enabled]

=== Command Line Tools

You need the following tools installed and configured to reach your cluster:

* https://kubernetes.io/docs/tasks/tools/[kubectl]
* https://kubectl.docs.kubernetes.io/installation/kustomize/[kustomize] (v4+ recommended)

== Installation

The application is distributed as a `kustomize` overlay named `standalone`. It provisions the backend, the UI, the database (PostgreSQL) with a nightly backup `CronJob`, the embedded object storage (MinIO), and an `Ingress`.

=== 1. Download the overlay

Clone the repository (or download the overlay directory) so you can edit the configuration files locally:

[source, shell script]
----
$ git clone https://gitlab.com/davinkevin/Podcast-Server.git
$ cd Podcast-Server/distribution/kubernetes/overlays/standalone
----

=== 2. Configure installation parameters

Edit `installation-parameters/kustomization.yaml` to set the domain served by the `Ingress` and the base directory used to store files on the host:

[source, yaml]
----
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

configMapGenerator:
  - name: installation-parameters
    literals:
      - location=/opt                     # <1>
      - domain=podcast.mydomain.local     # <2>
----
<1> Base directory on the host where the data (files, database, backups) will be stored. The overlay appends `/podcast-server/files/`, `/podcast-server/database/data`, `/podcast-server/database/init` and `/podcast-server/database/backup/` to this path.
<2> Domain served by the `Ingress`.

=== 3. Override default passwords

The `standalone` overlay ships with default passwords for the database, the object storage, and a placeholder for the Youtube Data API key. *You must override them before applying the manifests.*

Edit `kustomization.yaml` (the one in the `standalone/` directory) and update the `secretGenerator` section:

[source, yaml]
----
secretGenerator:
  - name: database
    behavior: merge
    literals:
      - password=<a strong password>
  - name: podcast-server
    behavior: merge
    literals:
      - api.youtube=<your Youtube Data API key>     # <1>
    type: Opaque
  - name: storage
    behavior: merge
    literals:
      - password=<a strong password>
----
<1> Optional. Set a Youtube Data API key if you plan to consume Youtube podcasts.

=== 4. Create the host directories

The overlay mounts host directories for the podcasts, the database files and the database backups. Create them on the node(s) scheduled to run the workloads, using the same base path you configured at step 2:

[source, shell script]
----
$ export PODCAST_SERVER_LOCATION=/opt/podcast-server
$ mkdir -p \
    $PODCAST_SERVER_LOCATION/files/ \
    $PODCAST_SERVER_LOCATION/database/data \
    $PODCAST_SERVER_LOCATION/database/init \
    $PODCAST_SERVER_LOCATION/database/backup/
----

=== 5. Apply

From the `standalone/` directory:

[source, shell script]
----
$ kustomize build . | kubectl apply -f -
----

After a few minutes (images pulling and the init-db `initContainer` bootstrapping the schema), the application will be reachable at the configured domain.

== Optional parameters

The backend reads the following optional keys from the `podcast-server` `ConfigMap`:

* `concurrent-download`: number of concurrent downloads.
* `max-update-parallels`: number of concurrent feed updates.
* `number-of-day-to-download`: retention for downloaded items.
* `number-of-day-to-save-cover`: retention for covers.

Add them to the `kustomization.yaml` of the `standalone/` directory via a `configMapGenerator` entry:

[source, yaml]
----
configMapGenerator:
  - name: podcast-server
    behavior: merge
    literals:
      - concurrent-download=3
      - max-update-parallels=3
      - number-of-day-to-download=30
      - number-of-day-to-save-cover=365
----
